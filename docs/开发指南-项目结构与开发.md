# 开发指南：项目结构与开发

> 本文档详细说明项目的代码组织方式、分层架构，以及如何正确地添加新功能。适用于熟悉 ThinkPHP 基础、但第一次接触本项目的开发者。

---

## 1. 架构总览

### 1.1 为什么从单应用改成多应用？

| 对比项 | 单应用（旧） | 多应用（新） |
|--------|-------------|-------------|
| URL 结构 | `/login/doLogin` | `/api/v1/auth/login` |
| 接口归属 | 所有接口混在 `app/controller/` | 接口集中在 `app/api/` |
| 路由文件 | 单个 `route/app.php` | 按应用拆分 |
| 前端入口 | 与接口混在一起 | 独立走根路由（SPA 回退） |

**核心思想**：本项目本质是「API 服务 + 前端页面」两个独立职责。多应用模式让这两者物理隔离：

- 访问 `/api/v1/*` → 进入 **api 应用**（纯接口，返回 JSON）
- 访问 `/`、`/app/*` → 进入**根路由**（返回 Vue 构建的 HTML 页面）

### 1.2 URL 如何路由到代码

```
http://localhost:8001/api/v1/auth/login
                        └┬┘ └┬┘ └┬┘ └┬┘
                         │   │   │   └─ 方法名 login()
                         │   │   └───── 控制器名 Auth
                         │   └─────────── 版本号 v1
                         └─────────────── 应用名 api（决定走 app/api/）
```

ThinkPHP 的 `MultiApp` 中间件看到 URL 第一段是 `api`，就把后续路径交给 `app/api/route/app.php` 处理，而 `/api` 前缀本身被剥离。

## 3. 三层架构详解

本项目遵循严格的分层，这是最重要的设计原则：

```
┌─────────────────────────────────────────────────┐
│  Controller（控制层）                            │
│  - 接收 HTTP 请求                                │
│  - 参数校验（调 ModelValidate）                  │
│  - 调 Service 拿结果                             │
│  - 返回统一 JSON 响应                            │
│  ❌ 不写业务逻辑、不写 SQL                       │
└──────────────────────┬──────────────────────────┘
                       │ 调用
┌──────────────────────▼──────────────────────────┐
│  Service（业务逻辑层）                           │
│  - 业务流程编排（登录=查用户→验密码→发token）     │
│  - 事务处理                                      │
│  - 抛业务异常 ApiException                       │
│  ❌ 不直接写 SQL、不处理 HTTP                     │
└──────────────────────┬──────────────────────────┘
                       │ 调用
┌──────────────────────▼──────────────────────────┐
│  Repository（数据访问层，db/ 目录）              │
│  - 数据库 CRUD                                   │
│  - 只做数据操作，返回数组/null                    │
│  ❌ 不写业务逻辑                                  │
└─────────────────────────────────────────────────┘
```

### 3.1 为什么要分层？

- **单一职责**：每层只做一件事，代码好维护
- **可测试**：可以单独测试 Service 层逻辑
- **可复用**：Service 可被多个 Controller 复用
- **易扩展**：改数据库不影响业务逻辑（比如将来从 MySQL 换 MongoDB）

### 3.2 各层代码示例

**数据访问层（db/db_user.php）**：
```php
class db_user extends Base
{
    protected $table = 'user';

    public function findByUsername(string $username): ?array
    {
        return $this->getOne(['username' => $username]);
    }
}
```

**业务逻辑层（app/common/service/AuthService.php）**：
```php
class AuthService
{
    public function login(string $identifier, string $password, string $ip, string $ua): array
    {
        $user = $this->dbUser->findByLogin($identifier);
        if (!$user || !password_verify($password, $user['password'])) {
            throw new ApiException(40102, '用户名或密码错误', 401);
        }
        // ... 签发 token
        return ['access_token' => $accessToken, ...];
    }
}
```

**控制层（app/api/controller/v1/AuthController.php）**：
```php
class AuthController extends BaseController
{
    public function login()
    {
        $params = $this->request->param();
        // 校验参数
        $check = (new ModelValidate())->check([...], [...], $params);
        if ($check['code'] !== 0) {
            return ApiResponse::error(40000, $check['msg'], 400);
        }
        // 调服务
        $result = $this->authService->login($params['identifier'], $params['password'], ...);
        return ApiResponse::success($result, '登录成功');
    }
}
```

## 4. 添加新功能的完整流程

假设要添加一个「获取用户统计」接口，完整的五步：

### 第 1 步：数据访问层（db/）

在 `db/db_user.php` 添加数据查询方法：

```php
// 统计某日注册用户数
public function countByDate(string $date): int
{
    return $this->table()
        ->where('create_time', '>=', $date . ' 00:00:00')
        ->where('create_time', '<=', $date . ' 23:59:59')
        ->count();
}
```

### 第 2 步：业务逻辑层（app/common/service/）

新建 `app/common/service/UserStatService.php`：

```php
<?php
declare(strict_types=1);

namespace app\common\service;

use db\db_user;

class UserStatService
{
    private db_user $dbUser;

    public function __construct()
    {
        $this->dbUser = new db_user();
    }

    public function dailyCount(string $date): array
    {
        return [
            'date'  => $date,
            'count' => $this->dbUser->countByDate($date),
        ];
    }
}
```

### 第 3 步：控制器（app/api/controller/v1/）

在 `UserController.php` 添加方法：

```php
public function stats()
{
    $date = (string) $this->request->param('date', date('Y-m-d'));
    $service = new \app\common\service\UserStatService();
    $data = $service->dailyCount($date);
    return ApiResponse::success($data);
}
```

### 第 4 步：路由（app/api/route/app.php）

在 `v1/user` 路由组内添加：

```php
Route::group('v1/user', function () {
    // ... 已有路由
    Route::get('stats', 'v1.User/stats');  // 新增
})->middleware(JwtAuth::class);
```

### 第 5 步：测试

```bash
# 登录拿 token
curl -X POST http://localhost:8001/api/v1/auth/login \
  -d "identifier=admin&password=Admin@123456"

# 用 token 访问新接口
curl http://localhost:8001/api/v1/user/stats?date=2026-08-18 \
  -H "Authorization: Bearer <token>"
```

## 5. 关键设计模式

### 5.1 统一响应体

所有接口返回相同结构：

```json
{ "code": 0, "message": "success", "data": {} }
```

| code | 含义 | HTTP 状态 |
|------|------|----------|
| 0 | 成功 | 200 |
| 40000 | 参数错误 | 400 |
| 40100 | 未登录 | 401 |
| 40101 | Token 过期 | 401 |
| 40102 | 用户名密码错误 | 401 |
| 40103 | 账号禁用 | 401 |
| 40105 | 账号锁定 | 401 |
| 40300 | 无权限 | 403 |
| 40900 | 资源冲突（重复） | 409 |
| 42900 | 请求频繁 | 429 |

使用方式：控制器里 `return ApiResponse::success($data)` 或 `return ApiResponse::error(40000, '参数错误', 400)`。

### 5.2 业务异常

Service 层通过抛异常来表达业务错误，由全局 `ExceptionHandle.php` 统一转为 JSON：

```php
throw new ApiException(40300, '无权限访问', 403);
```

### 5.3 参数验证器

控制器里统一用 `ModelValidate` 校验，失败返回统一错误：

```php
$check = (new ModelValidate())->check(
    ['username' => 'require|min:2|max:20'],
    ['username.require' => '用户名不能为空'],
    $params
);
if ($check['code'] !== 0) {
    return ApiResponse::error(40000, $check['msg'], 400);
}
```

支持规则：`require`、`email`、`mobile`、`code`、`min`、`max`、`length`、`confirm`、`in`、`isEmpty`。

### 5.4 中间件

| 中间件 | 作用 | 用法 |
|--------|------|------|
| `JwtAuth` | 验证 JWT，注入用户信息 | `->middleware(JwtAuth::class)` |
| `Permission` | 检查角色 | `->middleware(Permission::class, 'admin')` |
| `Throttle` | 限流 | `->middleware(Throttle::class, 'login')` |

## 7. 常见问题

**Q：Service 和 Controller 的区别是什么？**
Controller 只做「接参数、校验、返回」，Service 做「业务逻辑」。判断标准：如果一段逻辑将来可能被别的接口复用，就放 Service。

**Q：什么时候用 db/ 目录，什么时候用 ThinkPHP 的 Model？**
本项目统一用 `db/` 目录（自定义 Repository），**不使用** ThinkPHP 的 Model 层。这是有意的设计决策，避免双数据访问路径混乱。

**Q：路由定义在哪？**
API 接口在 `app/api/route/app.php`，前端 SPA 回退在根目录 `route/app.php`。

**Q：怎么加新的中间件？**
在 `app/api/middleware/` 建类，实现 `handle(Request $request, Closure $next)`，然后在路由里通过 `->middleware()` 挂载。
